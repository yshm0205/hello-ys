# 반주 미리듣기 회귀 수정

기준: 기존 Render `/kimatchum` 공개 HTML과 운영 복원본 e6772d4 비교.

원인:
- 기존 Render는 조표/코드 추정 키를 바로 선택하고 재생했다. 복원본은 `readyForPlayback`에서 `keyConfirmed=false`이면 전체 재생을 막았다.
- `readyForPlayback`과 `playbackEvents` 양쪽에서 코드 하나라도 해석 불가이면 전체를 막았다. 실제 후회 원본에는 54개 중 해석 불가 2개가 있어 이 조건도 재현됐다.
- 조표를 못 읽으면 음표 키 선택을 `-1`로 숨겼다. 코드로 A를 추정해도 사용자가 두 키를 재확인해야 했다.
- 음역·팀 범위 확인 및 개별 코드 검토 여부는 실제 재생 차단 조건이 아니었다. 안내 문구와 원키 차단이 전체 검토를 요구하는 인상을 줬다.
- 단일 곡 `startPlay`가 원래/바꾼 키 보기 토글을 무시하고 항상 목표 키를 사용했다.

수정:
- 기존 우선순위(조표 → 코드 추정)로 기본 키를 표시하고 음표 키에도 임시 추정값을 채운다. 수동 변경은 보존한다. 자동 추정 근거가 없거나 충돌하면 이를 명시한다.
- 후보 비교·코드 미리듣기·여러 곡 미리듣기는 원키/음역/전체 코드 검토 체크를 요구하지 않는다. 해석 불가 코드는 개수를 알리고 건너뛴다. 재생 가능한 내용이 없을 때만 안내한다.
- 원래 키 토글은 원키, 바꾼 키 토글은 목표 키로 재생한다. 오디오 컨텍스트가 실행되지 못하면 안내한다.
- 원본 보존 출력과 원본 위 교체 검토를 분리한다. 덮어쓰기에는 원키·코드·영역 확인을 계속 요구한다. 관련 원키 체크는 4번 출력 영역으로 옮겼다. 음역 확인은 선택 사항으로 표시한다.
- 멜로디·원곡 리듬·가창 적합성 미검증 표시는 유지한다. 인증·유료 AI·메일·저장소 권한은 변경하지 않는다.

검증:
- `tests/kimatchum-preview.test.cjs`: 자동 추정/수동 유지, 미검토 미리듣기, 해석 불가 코드 건너뛰기, 원래/전조 이벤트, 출력 보호 4개 회귀 테스트.
- 실제 `no-regret-A.png` 773×951 RGBA 브라우저 OCR → 코드/음표 A키 자동 선택 → 체크 없이 후보 12개와 반주.
- 실제 Next 작업실 iframe에서 AudioContext `running`, 발진 이벤트, analyser 비영점 파형 확인. 첫 기본음 A3=220Hz, B키 전환 비율 2^(2/12) 확인. 일시정지/재개/정지 확인.
- 해석 불가 코드 삽입 후 나머지 재생, 미검토 원본 덮어쓰기 차단, 원본 보존 A4 생성 확인.
- 증거: `trial-tests/preview-playback-integrated-result.json`, `preview-playback-integrated.png`.

검증 한계: 오디오 신호 생성을 검증했으며 사용자의 기기 스피커/음량·원곡 음악 정확도를 검증했다는 뜻은 아니다. 공개 OCR 모델 다운로드만 사용했고 AI·메일 호출은 없었다. 운영 반영 전 별도 확인 필요.
